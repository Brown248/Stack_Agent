# RESOURCES.md Format

`RESOURCES.md` is the curated set of trusted sources for this topic. Knowledge for lessons should be drawn from here, not from the model's memory. Wisdom comes from the communities listed here.

## Structure

```md
# {Topic} Resources

## Knowledge

- [Book: _Title of a foundational textbook_, by Author A and Author B](https://example.com)
  Foundational text on the topic. Use for: planning a long-term progression and judging intensity.
- [Article: "Title of a review article"](https://example.com)
  Evidence-based review of one sub-topic. Use for: setting weekly targets.

## Wisdom (Communities)

- [Name of an online forum](https://example.com)
  High-signal forum, moderated against unsupported claims. Use for: plan critique, troubleshooting a plateau.
- Local: weekly class at {venue name}
  Use for: real-time coaching feedback.
```

## Rules

- **High-trust only.** Prefer primary sources, recognised experts, peer-reviewed work, and communities with strong moderation. If a resource is marketing dressed as education, leave it out.
- **Annotate every entry.** A bare link is useless in three months. Add one line: what it covers and when to reach for it.
- **Group by Knowledge / Wisdom.** Mirrors the philosophy in [SKILL.md](./SKILL.md). It is fine for a resource to appear in only one group.
- **Surface gaps explicitly.** If no good resource exists for an area the mission needs, write a `## Gaps` section listing what is missing. This drives future search.
- **Add only sources you have opened.** Do not add a link or a title from memory. If a source could not be opened, leave it out or list it under `## Gaps`.
- **Prune ruthlessly.** A resource that turned out to be wrong, shallow, or off-mission should be removed, not buried. Better five sharp sources than thirty mediocre ones.
- **Record community preferences.** If the user has opted out of joining communities, note it here so future sessions don't keep proposing them.
